Qu'est-ce qu'un token ?

Un token n'est ni un mot, ni un caractère. C'est la brique atomique avec laquelle un modèle de langage lit, pense et génère du texte. Le processus de découpage s'appelle la tokenisation.

BPE (Byte-Pair Encoding)

Algorithme qui fusionne les paires de caractères les plus fréquentes lors de l'entraînement.

Unité de facturation

Chaque token en entrée et en sortie est comptabilisé et facturé par les API.

Astuces d'optimisation

Réduire le nombre de tokens sans sacrifier la qualité — c'est de l'ingénierie, pas de la magie.

  • 1

    Raccourcir le system prompt

    Chaque requête renvoie l'intégralité du prompt système. Un prompt de 2 000 tokens × 10 000 requêtes = 20 M tokens facturés inutilement.

  • 2

    Préférer l'anglais pour le code et les instructions

    Les tokenizers sont entraînés majoritairement sur de l'anglais. « Write a function » coûte souvent moins cher que « Écris une fonction » pour un résultat équivalent.

  • 3

    Limiter max_tokens en sortie

    Fixez un plafond réaliste. Un max_tokens à 4 096 pour une réponse attendue de 200 tokens gaspille de la marge de contexte et peut inciter le modèle à être verbeux.

  • 4

    Résumer l'historique de conversation

    Au-delà de 20–30 échanges, compressez les tours anciens en un résumé structuré plutôt que de renvoyer l'historique complet.

  • 5

    Éviter le JSON verbeux

    Préférez des clés courtes ("n" vs "customer_name") et supprimez les champs null ou vides avant injection dans le contexte.

Cache de prompt (Prompt Caching)

Anthropic et OpenAI proposent une mise en cache des prefixes identiques. Un system prompt stable peut coûter jusqu'à 90 % moins cher après le premier appel.

// Anthropic — marquer les blocs cacheables { "system": [{ "type": "text", "text": "Long contexte stable…", "cache_control": { "type": "ephemeral" } }] }

Token counting avant envoi

Utilisez les SDK officiels pour estimer le coût avant l'appel : tiktoken (OpenAI), anthropic.count_tokens(), ou l'API /v1/tokenize de Mistral.

RAG : chunking intelligent

Des chunks de 256–512 tokens avec overlap de 10–20 % offrent le meilleur compromis entre précision de retrieval et consommation de contexte. Évitez les chunks > 1 024 tokens sauf cas documentaire.

Structured outputs vs prose

Demander « réponds en JSON avec les clés a, b, c » consomme moins de tokens de sortie qu'une réponse en paragraphes, et facilite le parsing côté application.

Les vocabulaires des tokenizers sont surtout entraînés sur de l'anglais. Un mot français fréquent peut occuper 1 token, mais les mots composés, les accents et la morphologie riche produisent souvent 1,3 à 1,5 token par mot contre ~1,0 en anglais.
